After **each** later phase: list created/modified files, explain implementation, report actual tests and known limitations, verify source-drive protection, and **stop for approval**. Never scan `D:\` during development by default. Preserve existing application and research data; use synthetic fixtures and disposable workspaces.

## Test strategy and safeguards

Use synthetic files only, generated in temporary directories outside any research root; record before/after names, sizes, timestamps, attributes and, **only for test fixture verification**, fixture byte digests if needed. Instrument/monkeypatch all scanner source-file open calls to fail; audit dependencies and subprocess/network operations. Never hash or open real scanned documents, even for a test. Inject exceptions for permission, disappearing entries, writes and traversal; test cancellation mid-large-directory and recovery; verify `discovered = collected + skipped/failures` under defined semantics. Test exact aggregates against manually computed fixture data; label sampling, exclusions, approximation and denominator. Verify two scans of the same root remain distinct and sources unchanged. Keep a clear division between imported metadata bytes and scanned file contents. Do not run a destructive legacy database rebuild.

Performance tests generate millions of **synthetic metadata rows** rather than millions of source documents first; measure peak RSS and disk growth, exact aggregate queries, cancellation latency and time-to-first-chart, and disclose machine and dataset characteristics. Then limited-size real traversal of a disposable synthetic tree. Full-drive scanning is a separate user-approved acceptance step, never a development default.

## Windows 11 validation checklist (future, not performed here)

* In a disposable checkout and virtual environment, install a reviewed pinned set only after approval. Point all temp/cache, test roots and app outputs at dedicated synthetic locations outside protected research directories. Run unit/integration tests with paths redirected and record exact Windows, Python and dependency versions, test commands, outputs, pass/fail/skip.
* Use the native directory dialog against synthetic drive/folder examples; confirm whole-drive detection without walking the drive. Test the approved output policy with case variants, trailing separators, prefixes that merely look similar, UNC/extended-length paths, volume aliases, link targets, root selection and output-inside-source rejection/approved enclave pruning.
* Create disposable NTFS directory junctions and symlinks where permitted; check reparse attributes, linked root, cycles, denied directories/ACLs, long and Unicode paths, file disappearance and readonly attributes. Skip with reasons when privileges or filesystem support are absent. Validate APIs on supported Python versions; do not assume Linux results prove Windows behavior.
* Check timestamp source/availability and timezone/DST behavior on actual Windows filesystems; compare creation and modification separately and document Windows/Python differences. Exercise cancellation and shutdown during traversal, output batching and report generation; validate status and cleanup/recovery.
* Test WebEngine offline with local Plotly assets, chart interaction/export, PDF/PNG/SVG and packaging without internet, source unchanged, configured exclusion and no telemetry. Only after explicit separate consent conduct any real-drive acceptance scan; initial development does not scan `D:\`.
